# 实验日志

> 复制本文件到新赛题的 `docs/experiments.md`，然后按下面的规则往里记。
> 这份日志的价值不在"记了什么"，而在**每条结论都有证据、每条失败都有原因**。

## 报告规则（先读）

**只有「按源图分组留出折 + 冻结官方评分脚本」得到的分数才算证据。**

测试集无标注时，任何其他口径的数字（按图随机划分、单折挑好的、本地快速评测器）
一律标成 `LEAKY`，**不得用于决策**。

## 配对规则（代价换来的）

**任何改动的结论必须来自 5 折配对比较。**

单折 140 图的 mAP 噪声在 **±0.7 pp** 量级。真实案例：某改动在 fold-4 上看着涨
**+0.88 pp**（像明确胜利），补齐 5 折后均值只有 **+0.18 pp**、标准差 0.69 pp ——
与 0 无法区分，该改动被否掉。

**采纳门槛：均值 ≥ 0.5 pp，且不能只有 1 折变好。**
报告时必须给出：逐折分数、均值、标准差、胜负比。

## 实验条目模板

### E1 · YYYY-MM-DD · <一句话描述改动>

- 假设   : 为什么认为它会更好（先写假设，再看结果，避免事后编故事）
- 改动   : **唯一变量**是什么；其余全部不变
- 命令   : 可复现的完整命令
- 结果   : 5 折逐折分数 + 均值 + 标准差 + 胜负比
- 结论   : 采纳 / 否掉 / 无结论（附一句理由）
- 留痕   : 改动的文件、提交号

## 缺陷留痕（实现层的坑，比实验结论更容易复现）

| 日期 | 缺陷 | 修正 |
|---|---|---|
| | | |

记录要点：**现象**（报错原文或异常数字）、**根因**（不是"修好了"，而是"为什么"）、
**检测手段**（下次怎么更早发现）。值得记的类型：

- 训练"跑满轮数、loss 正常"但其实没在训练（检测手段：对 checkpoint 权重取哈希比对）
- 验证口径错误导致分数虚高（源图跨折、泄漏）
- 打包/提交链路的静默失败（多一个文件、SHA 不匹配、重压归档）
- 跨设备复现差异（判定应按指标容差，而非逐字节相等）
